# NAVAREA Bot

Telegram-бот для моряков. Следит за навигационными предупреждениями NAVAREA/NAVTEX по выбранным районам, присылает новые прямо в чат, отвечает на вопросы по судовождению через Claude, разбирает текст конкретного предупреждения простым языком. Есть бесплатный тариф и платная подписка на 3$/месяц через Telegram Stars.

Этот файл — гайд с нуля. Рассчитан на то, что ты не касался кода вообще. Если что-то будет непонятно по ходу, спрашивай, дальше разберёмся.

## Что нужно, прежде чем начать

- Аккаунт Telegram (есть)
- Аккаунт GitHub — заведём по ходу, бесплатно
- Аккаунт Anthropic для ключа Claude — заведём по ходу, для оплаты понадобится карта (хватит пары долларов на первое время)
- Где-то в середине гайда будет выбор сервера: Oracle Cloud (нужна карта для верификации, без списаний) или Render+Neon (карта вообще не нужна, но чуть больше отдельных шагов). Про оба варианта ниже, можно выбрать по ходу
- Часа полтора-два свободного времени один раз. Дальше бот работает сам, без твоего участия

Всё делается с ноутбука или компьютера, не с телефона — часть шагов (терминал) на телефоне неудобна.

## Шаг 1. Получить токен бота

1. Открой Telegram, найди **@BotFather** (это официальный бот Telegram, у него синяя галочка)
2. Напиши `/newbot`
3. Придумай имя бота (то, что видят люди, можно на русском, например "NAVAREA Monitor")
4. Придумай username бота — он обязательно должен заканчиваться на `bot`, например `kirk_navarea_bot`. Если имя занято, придумай другое
5. BotFather пришлёт сообщение с токеном — длинная строка вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`. Скопируй её куда-нибудь (заметки, файл) — она ещё понадобится

Токен — это как пароль от бота. Никому его не показывай и никуда не выкладывай напоказ (в публичный код в том числе).

## Шаг 2. Узнать свой Telegram ID

Это нужно, чтобы бот понимал, что именно ты — владелец, и пускал тебя в админ-команды.

1. Найди в Telegram **@userinfobot**
2. Напиши `/start`
3. Он пришлёт твой Id — набор цифр. Тоже сохрани

## Шаг 3. Получить ключ Claude

1. Зайди на **console.anthropic.com**, зарегистрируйся
2. Слева найди **Settings → API Keys**, нажми **Create Key**, скопируй ключ (начинается на `sk-ant-`). Он показывается один раз, сразу сохрани
3. Там же в **Billing** пополни баланс на 5-10$ — с Claude Haiku (модель по умолчанию в боте) этого хватит очень надолго, вопрос стоит доли цента

## Шаг 4. Залить код на GitHub

GitHub — это просто место, где будет храниться код бота, чтобы сервер мог его оттуда скачать.

1. Зайди на **github.com**, зарегистрируйся
2. Разархивируй `navarea-bot.zip`, который я прислал, себе на компьютер (просто в папку)
3. На GitHub нажми **+** в правом верхнем углу → **New repository**
4. Название repository впиши ровно **navarea-bot** (это важно, дальше пути в гайде на это рассчитаны), Public или Private — без разницы, выбирай Private если не хочешь чтобы код видели посторонние
5. Нажми **Create repository**
6. На следующей странице нажми ссылку **uploading an existing file**
7. Перетащи туда ВСЕ файлы и папки из разархивированной `navarea-bot` (можно выделить всё и перетащить одним разом, GitHub сам разложит по папкам)
8. Внизу нажми **Commit changes**

Готово, код теперь лежит на GitHub. `.env` файл (с секретными ключами) в архиве нет специально — его создашь прямо на сервере на следующем шаге, чтобы ключи никогда не попадали в GitHub.

## Шаг 5. Выбрать где будет жить сервер

Дальше бот должен работать на каком-то компьютере 24/7, независимо от твоего интернета. Два бесплатных варианта:

|  | Oracle Cloud | Render + Neon |
|---|---|---|
| Нужна карта | да, только для проверки, не спишут | нет, вообще нигде |
| Проверка личности | строгая, иногда отказывает без явной причины | практически нет |
| Сложность настройки | больше (сервер, терминал, SSH) | меньше (в основном кнопки в браузере) |
| Надёжность в долгую | максимальная, свой сервер | хорошая, но два внешних сервиса вместо одного |

Раз у тебя Oracle уже не пускает — переходи сразу к **варианту Б** ниже, он не требует той верификации, на которой всё застряло. Если позже захочешь всё же разобраться с Oracle, чуть ниже в частых вопросах есть чек-лист, что обычно помогает.

### Вариант А. Oracle Cloud (свой сервер, диск постоянный)

Почему в принципе Oracle, а не более простые Railway/Render — они либо просят деньги уже через месяц, либо (это важно) стирают базу данных бота при каждой перезагрузке сервиса. То есть все подписчики, районы, оплаченный Premium — обнулялись бы. У Oracle настоящий диск, который никуда не девается.

1. Зайди на **cloud.oracle.com/free**, нажми **Start for free**
2. Заполни форму (страна, имя, почта), подтверди почту по коду
3. Введи телефон, подтверди по SMS
4. Введи данные карты для верификации — спишется 0, максимум может на пару дней зависнуть небольшой холд, потом вернётся
5. Дождись подтверждения аккаунта (обычно быстро, иногда до пары часов)
6. Залогинься в **Oracle Cloud Console**

Дальше создаём сам сервер:

7. В верхнем левом углу — гамбургер-меню (☰) → **Compute** → **Instances**
8. Нажми **Create instance**
9. Дай имя, например `navarea-server`
10. В блоке **Image and shape** нажми **Edit**
11. Образ (Image) оставь **Ubuntu** (если стоит другой — смени на Ubuntu, последнюю версию из списка)
12. Нажми **Change shape**. Тут важный момент: не бери ARM/Ampere (A1) — она популярная и почти всегда пишет "Out of capacity". Вместо этого выбери вкладку **Specialty and previous generation** и там **VM.Standard.E2.1.Micro** — эта не пользуется спросом и создаётся всегда без ошибок. Ресурсов (1 CPU, 1 GB памяти) боту хватает с большим запасом
13. Дальше блок **Add SSH keys** — оставь **Generate a key pair for me**, нажми **Save private key** — скачается файл вроде `ssh-key-....key`. Это ключ для входа на сервер, сохрани его в удобное место (например в папку с проектом) и не теряй, второй раз не выдадут
14. Больше ничего не трогай, внизу нажми **Create**
15. Подожди минуту-две, статус сменится на зелёный **Running**
16. На странице инстанса найди **Public IP address** — скопируй, это адрес твоего сервера

Дальше иди к шагу 6.

### Вариант Б. Render + Neon (без верификации личности)

Здесь сервер (Render) и база данных (Neon) — два разных бесплатных сервиса. Разделены специально: у Render бесплатный тариф не даёт постоянный диск (данные бота стирались бы при каждом перезапуске), а Neon — это как раз постоянное хранилище отдельно от сервера, полностью бесплатное и без карты. Плюс понадобится третий бесплатный сервис (UptimeRobot), который будет раз в несколько минут "стучаться" в бота, чтобы Render не усыплял его от бездействия.

**Сначала база данных, Neon:**

1. Зайди на **neon.tech**, зарегистрируйся (можно через GitHub-аккаунт, который уже завёл на шаге 4 — так быстрее)
2. Создай проект (**Create a project**), имя любое, например `navarea`
3. На странице проекта найди **Connection string** — это строка вида `postgresql://user:password@ep-xxxx.neon.tech/navarea?sslmode=require`. Скопируй её целиком, понадобится через пару шагов

**Дальше сам сервер, Render:**

4. Зайди на **render.com**, зарегистрируйся (тоже можно через GitHub)
5. Нажми **New** → **Web Service**
6. Подключи свой GitHub-аккаунт, если попросит, и выбери репозиторий **navarea-bot**
7. Заполни поля:
   - **Name** — любое, например `navarea-bot`
   - **Runtime** — Python 3
   - **Build Command** — `pip install -r requirements.txt`
   - **Start Command** — `python -m bot.main`
   - **Instance Type** — **Free**
8. Раскрой **Advanced** → **Environment Variables**, добавь по одной (кнопка **Add Environment Variable**):
   - `BOT_TOKEN` — токен из шага 1
   - `OWNER_IDS` — твой id из шага 2
   - `ANTHROPIC_API_KEY` — ключ из шага 3
   - `DATABASE_URL` — connection string из Neon (шаг 3 выше)
9. Нажми **Create Web Service** внизу

Render сам скачает код, установит зависимости и запустит бота — это займёт пару минут, прогресс видно в логах прямо на странице сервиса. Когда статус станет **Live** — иди в Telegram, напиши боту `/start`, должен ответить.

Сверху на странице сервиса будет ссылка вида `https://navarea-bot-xxxx.onrender.com` — скопируй её, нужна для последнего шага.

**Чтобы бот не засыпал:**

10. Зайди на **uptimerobot.com**, зарегистрируйся
11. **Add New Monitor** → тип **HTTP(s)**
12. В **URL** вставь ссылку на свой сервис из Render (шаг 9 выше)
13. **Monitoring Interval** — поставь 5 минут
14. Сохрани

Готово, дальше пропусти шаги 6-8 ниже (они про Oracle и терминал, на Render не нужны) и переходи сразу к шагу 9 про оформление бота в BotFather.

## Шаг 6. Подключиться к серверу

*(только для варианта А, Oracle — если ты на Render, пропусти сразу к шагу 9)*

На Windows: открой **PowerShell** (найди в поиске Пуск). На Mac: открой **Terminal**. Дальше команды одинаковые.

Впиши (замени путь к ключу и IP на свои):

```
ssh -i "путь/до/ssh-key-....key" ubuntu@ТВОЙ_PUBLIC_IP
```

Первый раз спросит "are you sure you want to continue connecting" — впиши `yes`.

Если Windows ругается на права доступа к файлу ключа ("UNPROTECTED PRIVATE KEY FILE") — смотри раздел с частыми вопросами внизу, там есть команда-исправление.

Если всё хорошо, увидишь приглашение вида `ubuntu@navarea-server:~$` — ты внутри сервера.

## Шаг 7. Установить бота на сервере

*(только для варианта А, Oracle)*

Дальше все команды вводятся прямо в этом окне терминала, по одной, с Enter после каждой.

Обновить систему и поставить нужные программы:

```
sudo apt update && sudo apt install -y python3-venv python3-pip git
```

Скачать код бота с GitHub (замени ТВОЙ-НИК на свой юзернейм на GitHub):

```
git clone https://github.com/ТВОЙ-НИК/navarea-bot.git
cd navarea-bot
```

Создать изолированное окружение Python и поставить зависимости:

```
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Создать файл с настройками:

```
cp .env.example .env
nano .env
```

Откроется текстовый редактор прямо в терминале. Впиши после каждого знака `=` свои значения из шагов 1-3 (токен бота, свой Telegram ID, ключ Claude), например:

```
BOT_TOKEN=123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
OWNER_IDS=111111111
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxxxxxx
```

Строку `DATABASE_URL` в этом варианте не трогай, оставь пустой — бот сам создаст файл SQLite на диске сервера. Остальные строчки тоже можно не трогать, там уже разумные значения по умолчанию. Сохранить и выйти из nano — `Ctrl+O`, потом `Enter`, потом `Ctrl+X`.

Проверочный запуск (это ещё не автозапуск, просто проверка что всё настроено верно):

```
python -m bot.main
```

Если видишь строчку `Бот запускается...` и нет ошибок красным — всё получилось. Иди в Telegram, найди своего бота по username и напиши `/start`. Должен ответить.

Останови проверочный запуск через `Ctrl+C`, дальше настроим автозапуск, чтобы бот работал постоянно, а не только пока открыт терминал.

## Шаг 8. Сделать так, чтобы бот работал всегда сам

*(только для варианта А, Oracle — Render перезапускает сам, без этого шага)*

Сейчас бот выключится, как только ты закроешь терминал. Чтобы он жил 24/7 и сам перезапускался при сбое или перезагрузке сервера, настроим systemd — стандартный способ в Linux запускать фоновые программы.

```
sudo nano /etc/systemd/system/navarea-bot.service
```

Вставь туда содержимое (у тебя в проекте есть готовый файл `deploy/navarea-bot.service` с этим же текстом, можно свериться):

```
[Unit]
Description=NAVAREA Telegram Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/navarea-bot
ExecStart=/home/ubuntu/navarea-bot/venv/bin/python -m bot.main
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Сохрани и выйди (`Ctrl+O`, `Enter`, `Ctrl+X`), потом включи:

```
sudo systemctl daemon-reload
sudo systemctl enable navarea-bot
sudo systemctl start navarea-bot
```

Проверь статус:

```
sudo systemctl status navarea-bot
```

Должно быть зелёным и написано `active (running)`. Нажми `q` чтобы выйти из этого экрана.

Теперь бот будет работать даже если ты закроешь терминал, выключишь ноутбук, уйдёшь в рейс без интернета — сервер живёт отдельно от тебя.

## Проверка что всё работает

В Telegram у своего бота проверь по очереди:

- `/start` — должно прислать приветствие
- `/areas` — покажет кнопки с районами, потыкай пару штук
- `/sources` — список всех 21 района с официальными источниками
- `/status` — покажет твой тариф и выбранные районы
- напиши любой вопрос текстом, например "какая осадка обычно у контейнеровоза" — должен ответить через Claude
- `/subscribe` — должен прислать кнопку оплаты в Stars (сама оплата спишет настоящие звёзды, для проверки достаточно убедиться что кнопка появляется)

## Как обновить бота, если что-то поправишь

В обоих вариантах хостинга обновление НЕ требует останавливать сервер руками и НЕ прерывает фоновый мониторинг районов дольше чем на несколько секунд — просто старый процесс бота заменяется новым с уже актуальным кодом, автоматически.

Меняешь файлы прямо в браузере на GitHub (открыть файл → карандаш редактировать → Commit changes).

Дальше, если вариант А (Oracle) — зайди по SSH и:
```
cd navarea-bot
git pull
sudo systemctl restart navarea-bot
```
Перезапуск через systemd занимает пару секунд — за это время бот просто не отвечает на сообщения, они не теряются (Telegram доставит их сразу как бот снова поднимется), а уже сохранённые в базе подписки и предупреждения никуда не деваются.

Если вариант Б (Render) — вообще ничего делать не надо. Render сам видит изменения на GitHub и передеплоивает сервис заново (видно во вкладке **Events**), Neon как отдельная база данных это редеплой вообще не затрагивает.

## Частые вопросы

**Сколько всё это будет реально стоить в месяц?**
И Oracle, и связка Render+Neon+UptimeRobot — 0$, это постоянные бесплатные тарифы без срока действия. Claude Haiku при паре сотен вопросов в месяц — обычно центы, редко больше 1-2$. То есть почти вся подписочная выручка 3$/мес с человека остаётся чистой прибылью.

**У меня как у владельца бота Premium без оплаты, как это работает?**
Твой Telegram-id из шага 2 (тот, что вписан в OWNER_IDS) автоматически даёт полный доступ без реальной оплаты через Stars — это привязано именно к числовому id, а не к @username, потому что боты в Telegram технически видят только числовой id, а не ник (ник можно сменить в любой момент, id — нет). Так что если OWNER_IDS уже заполнен твоим id — Premium уже работает, ничего дополнительно включать не надо. Проверить можно командой `/status`, должно быть написано "доступ владельца бота".

**Oracle пишет "Не удалось завершить регистрацию", что делать?**
Это частая история, у Oracle довольно резкая автоматическая проверка на мошенничество, и она иногда блокирует совершенно нормальные регистрации без понятной причины (это не только у тебя, это массово встречается у людей из самых разных стран). Прежде чем сдаваться, стоит проверить:
- Выключен ли VPN/прокси — Oracle сверяет страну по IP с тем, что вписано в форме, и палит подмену
- Карта настоящая, не виртуальная и не предоплаченная, поддерживает международные платежи
- Имя, фамилия и адрес в форме регистрации совпадают с тем, что указано у карты, буква в букву
- Почта, которая раньше нигде в Oracle не использовалась
- Попробовать в приватном/инкогнито окне браузера, без расширений, предварительно почистив куки

Если после аккуратной проверки всех пунктов ошибка повторяется — не трать на это больше времени, переходи на **вариант Б (Render + Neon)** из шага 5, он вообще не требует такой проверки личности.

**Что если при создании сервера на Oracle пишет "Out of host capacity"?**
Это отдельная, другая ошибка (уже после успешной регистрации) — значит выбран не тот shape. Убедись что выбрана именно **VM.Standard.E2.1.Micro** из вкладки Specialty and previous generation, а не Ampere A1 — с ней такое почти не случается.

**Windows пишет "UNPROTECTED PRIVATE KEY FILE" при подключении по SSH**
Это Windows считает файл ключа слишком "открытым". Исправляется командой в PowerShell (подставь свой путь к файлу):
```
icacls "путь\до\ssh-key-....key" /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

**Как получить настоящие деньги из Telegram Stars?**
Через встроенный в Telegram сервис Fragment — звёзды конвертируются в криптовалюту TON, дальше можно вывести. Ссылка появится в Telegram в разделе "Мои звёзды", когда наберётся баланс.

**Что если бот перестал отвечать?**
Вариант А (Oracle) — подключись по SSH тем же способом, что в шаге 6, и введи:
```
sudo systemctl status navarea-bot
journalctl -u navarea-bot -n 50
```
Первая команда покажет жив ли процесс, вторая — последние строчки логов с текстом ошибки, если она есть. Перезапустить вручную: `sudo systemctl restart navarea-bot`.

Вариант Б (Render) — открой render.com, зайди в свой сервис, вкладка **Logs** покажет то же самое без всякого терминала. Перезапустить — кнопка **Manual Deploy → Restart service** там же.

**Источник по Испании (NAVAREA III, Средиземное и Чёрное море) помечен экспериментальным, что это значит?**
Адрес рабочий и бот его реально опрашивает, но разбор текста на отдельные предупреждения сделан по образцу, который не с чем было сверить вживую при разработке (сайт не отдаёт мне сырые данные для теста). Скорее всего первое время будет присылать не идеально аккуратно (иногда дублирует кусок текста). Код лежит в `bot/services/sources/spain_ihm.py`, поправить можно в любой момент, когда увидишь на реальных данных что именно не так.

**Можно добавить ещё районы NAVAREA?**
Да, `bot/services/sources/registry.py` — таблица всех 21 района с их официальными источниками, какие есть на данный момент. Живых автоматических источников на старте три: NGA (США, районы IV, XII плюс HYDROLANT/HYDROPAC), UKHO (Великобритания, район I) и DHN (Перу, район XVI). Для остальных в реестре указан официальный сайт координатора, но рабочего автоматического разбора под него ещё нет — это то, что можно дописывать постепенно по той же схеме. По Пакистану (район IX) сайт явно блокирует автоматические запросы, туда лучше не лезть.

**Обязательно ли постоянно быть онлайн, чтобы бот работал?**
Нет, в обоих вариантах бот живёт на чужом сервере сам по себе. Твой телефон, ноутбук, интернет на судне — вообще не при чём, это просто отдельный компьютер в дата-центре, который работает 24/7.

**Можно ли начать с Render, а потом переехать на Oracle если получится с регистрацией?**
Да, без проблем, база данных ни там ни там не привязана намертво. На Oracle просто оставь `DATABASE_URL` пустым (заведётся SQLite-файл), а если захочешь перенести уже накопленные данные с Neon — напиши, помогу с переносом.
